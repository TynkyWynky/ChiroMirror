## Corrections

- Connexion, contrôle de session, récupération et changement de mot de passe :
  délais maximum, bouton occupé, erreurs visibles et reprise après échec.
- Requêtes Supabase : interruption des requêtes et corps de réponse bloqués,
  y compris lors du chargement des modules et du rendu du site public.
- Session : protection contre une ancienne réponse qui écrase un état plus récent;
  connexion possible en mémoire lorsque le navigateur refuse son stockage.
- Invitations/récupération : le code à usage unique n'est échangé qu'une fois.
- Installation APP absente : explication visible; le SITE reste accessible aux
  comptes qui y ont droit. Aucun droit n'est attribué automatiquement.
- Navigation PC : boutons **SITE / APP** en tête du menu, selon les droits.
- Démarrage local : correction du traitement du module HTML côté développement;
  émulation Edge/Images Netlify désactivée pour éviter sa dépendance Deno locale.
- Production : regroupement des dépendances du nettoyeur HTML pour éviter les
  erreurs `require(ESM)` dans la fonction Netlify.
- API contact et suppression d'équipe : les entrées malformées sont rejetées;
  `null` ne provoque plus une exception de validation.
- Contact : attente limitée à 15 secondes et formulaire réutilisable après un
  incident réseau; annonce accessible du résultat.
- Dépendances : Astro 7.3.5, intégration Netlify 8.2.6, intégration Preact 6.0.5,
  Preact 10.29.8, Supabase 2.117.1, Marked 18.0.14 et mises à jour compatibles
  transitives. Retrait des anciens patchs manuels de `node_modules`, leurs
  corrections étant présentes dans les versions officielles.

## Ouvrir l'APP sur ce PC

Version locale corrigée : double-cliquer sur
[`Demarrer-Chiro.cmd`](../Demarrer-Chiro.cmd), ou exécuter :

```powershell

```

Puis utiliser <http://127.0.0.1:4321/leiding-login/?app=home>. Le terminal doit
rester ouvert; `Ctrl+C` arrête le serveur. Aucun serveur LAN n'est exposé par défaut.
Le chemin suit `ADMIN_PATH_SLUG` s'il est personnalisé.

Un `.env.local` ignoré par Git a été préparé avec l'URL et la clé **publique**
déjà utilisées par le site. Aucune clé privilégiée n'a été copiée. Cette version
locale utilise le même projet Supabase : le schéma APP distant doit être activé
pour accéder aux vrais modules et aux données du compte. Les invitations et le
stockage des contacts par les API locales exigent en plus la clé serveur.
Pour les liens de récupération locaux, autoriser l'URL locale dans Supabase Auth
comme indiqué dans le README.

## Terminer l'activation Supabase

Tous les fichiers suivants sont prêts et testés, mais **non exécutés à distance**.

1. Dans le SQL Editor du bon projet Supabase, exécuter
   [`verify-app.sql`](../supabase/verify-app.sql). C'est une lecture du schéma et
   des droits, sans modification de données.
2. Si les objets sont déjà présents, examiner les droits et l'historique; un
   `notify pgrst, 'reload schema';` peut suffire pour un cache périmé. Ne pas
   rejouer l'installation sur un schéma déjà installé ou partiellement installé.
3. Si aucune phase APP n'a été installée, sauvegarder la base et vérifier les
   prérequis indiqués en tête de [`install-app.sql`](../supabase/install-app.sql),
   puis exécuter ce fichier. Il regroupe le prérequis de compatibilité de l'ancien
   SITE (`managed_group_slugs`) et les six migrations APP dans **une seule
   transaction**, refuse les schémas partiels/déjà installés et conserve les
   comptes, contenus et rôles SITE existants. Une erreur annule l'ensemble.
4. Relancer `verify-app.sql`. Les 28 tables attendues doivent exister avec RLS
   active; les fonctions privées ne doivent pas être exécutables par `anon`.
5. Dans [`bootstrap-app-admin.sql`](../supabase/bootstrap-app-admin.sql), remplacer
   `REPLACE_WITH_VERIFIED_EMAIL` par l'e-mail exact du premier compte administrateur
   APP, puis exécuter. Le fichier refuse une adresse inexistante et n'attribue que
   `APP_ADMIN` à ce seul compte; il n'accorde ni SITE admin ni trésorerie.
6. Déployer les changements applicatifs via le circuit Netlify du dépôt, puis
   ouvrir le lien APP et se connecter. Dans **Membres**, créer/lier la fiche du
   compte pour les modules personnels et attribuer les rôles utiles aux autres
   comptes. Le rôle trésorier reste explicite.
7. Exécuter `npm.cmd run doctor:app`, puis vérifier avec le vrai compte la
   connexion, l'agenda, les tâches, les comptes et la déconnexion sur PC/mobile.

Le bundle se régénère avec `npm.cmd run prepare:app-install`; son contenu exact,
son ordre, son atomicité, le refus des installations répétées et le bootstrap
d'un seul compte sont couverts par les tests. Il ne lance jamais le seed et ne
remplace pas `schema.sql` sur une base existante. Réconcilier l'installation
manuelle avec l'historique avant un futur push Supabase CLI.

## Points ouverts

- Audit npm : **45 alertes avant, 8 après, aucune critique restante**. Les huit
  alertes élevées proviennent de la chaîne de développement Netlify autour
  d'`extract-zip` et d'une version transitive de `sharp`. La correction forcée
  proposée par npm rétrograderait l'adaptateur vers une version incompatible;
  elle n'a pas été appliquée. L'émulation locale des images et Edge est désactivée.
  Cela ne signifie pas que l'arbre de dépendances est exempt de vulnérabilités.
- Push réels : VAPID, worker planifié, activation volontaire et permissions du
  téléphone nécessitent une recette sur l'environnement déployé.
- Les anciens justificatifs de la finance SITE restent dans le bucket public
  `site-media`, comme documenté dans `app-foundation.md`. Aucune migration de
  fichiers privés ou modification d'URL existante n'a été improvisée.
- Aucun déploiement, octroi de rôle ni changement de base distante effectué.

Références techniques de la mise à jour :
[migration Astro 7](https://docs.astro.build/en/guides/upgrade-to/v7/) et
[correctif de sécurité Astro/AVIF](https://github.com/withastro/astro/security/advisories/GHSA-26w7-cxv4-gfx2).
